# Harness Adapter DOX

## Purpose

- Own the provider-neutral harness interface, catalog/factories, transactional supervisor, and Codex, Claude Code, Agent Zero CLI, Pi, and ACP process adapters.

## Local Contracts

- Keep application and orchestration code harness-neutral; adapters map native events into the common response and follow-up contract.
- Codex maps strictly boolean `error.willRetry: true` to nonterminal `reconnecting` status, retaining diagnostics in captured events. Only nonempty agent-message, reasoning, or plan deltas for the exact active turn restore `running`; tool output and generic activity do not establish upstream recovery. Missing/false/malformed retry flags remain errors. Serialize admission, deferred replay, live notifications, and transport failure through callback publication; publish admission first and reject another turn's late events. Transport failure also fences pending admission so a successful RPC reply cannot resurrect an exited provider.
- Resume Codex threads with `excludeTurns: true`: Codex retains its conversation context, while Spynel consumes only thread identity and its own bounded history. Resume failures preserve the saved session and reject dispatch, except an exact -32600 missing-rollout response for a chat session: create and persist a replacement thread, report recovery status, and use the ordinary prompt containing bounded Spynel history. Workflow sessions never take this fallback; failed replacement persistence restores the saved mapping. Keep the shared 16 MiB message bound; overflow and EOF close provider stdin as well as cancelling the subprocess so npm-launched native children receive EOF, fail pending/active work, and remain visibly unavailable through the supervisor until explicit restart or successful reconfiguration. Overflow diagnostics inspect only a bounded envelope prefix to identify a known notification or the correlated pending RPC, report unavailable metadata explicitly, and name the message-size limit and reconnect action without exposing payloads, provider IDs, arbitrary method strings, or replaying interrupted requests.
- Declare native-steer versus queued follow-up behavior explicitly, fence active executions, and invoke durable iteration reservation exactly once immediately before accepted provider delivery. NativeSteerer is non-owning: retain the current emitter without a done-status handoff. ConversationSteerer transfers the emitter only within an existing native turn, using that adapter's completion/input delivery fence. Strict Supervisor follow-ups require this operation for native adapters and never fall back to ordinary Send; absent/closing/completed turns provide explicit pre-delivery rejection, while delivery/acknowledgement failures remain uncertain. Queue-mode admission retains the existing serialized logical-execution queue.
- Expose the provider-neutral new/steered/queued conversation admission classification at the same session fence so application correlation can cover consolidated terminal responses exactly.
- Waiting for a Supervisor session operation honors the caller context before send, control queue/deduplication/reservation or interruption changes. Cancellation before admission leaves the active execution and retry authority untouched; an already-admitted queued continuation retains its owning lifetime. This does not bound other locks or undo uncertain provider delivery.
- Worker HTTP operations reuse that zero-value gate and honor the request context while waiting. Recheck cancellation after the separate exact-election acquisition before updating the worker's detached timestamp or applying any action, including shutdown. Expired unadmitted requests neither change execution/control state nor prolong worker detached lifetime. Already-admitted operations and queued continuations keep their original worker-owned lifetime; election-lock acquisition and its exact-term post-callback refresh retain their existing contract.
- A rejected ordinary native follow-up preserves the still-active original control emitter as well as the adapter emitter. Roll back that provisional owner under the existing session operation lock; never restore it after the original provider has ended. Later controls and their single continuation still belong to the admitted request.
- SendNotAdmittedError is the sole shared proof that a request reached neither provider execution nor its continuation queue. Mark only local pre-delivery validation, unavailable-target and cancelled session-admission failures; preserve the underlying error text/cause. Once prompt delivery may have started, including partial pipe writes, protocol errors and lost acknowledgements, an error remains uncertain. Callers must retain source correlation, avoid fabricated terminal coverage and never infer rejection from thread/activity/steering flags. An ordinary follow-up error retains its original thread/steering/error result. Concurrent provider completion never authorizes Supervisor to retry it as a new turn: the error does not prove non-delivery. A later explicit request uses normal admission; adapter-owned pre-delivery completion fences retain their own contracts.
- When an ordinary queued follow-up replaces an emitter, deliver its predecessor's continuing result followed by an explicit done-status release. This closes every request and balances application/channel activity without claiming logical completion. Orchestrator controls that preserve their emitter do not release it.
- An interruption attempt cancels not-yet-dispatched ordinary follow-ups with a terminal error per request, including every emitter in a dequeued batch. Capture the cancellation generation when removing queued work, preserve it through batching, and reject stale dispatch even if a successor turn is active. Queued controls retain their shared emitter; only the provider owns that execution's terminal event. Failure to interrupt the active provider does not restore already-cancelled queued requests.
- Order forward-looking model commits and dispatch snapshots under one supervisor fence. Never mutate an already-admitted provider turn; native steering remains part of that turn, while queued continuations and later top-level turns snapshot the newest model at their own provider-dispatch admission.
- Extend that fence to reasoning effort and service mode. Catalog metadata declares effort support for Codex, Claude, and Pi. Their model and effort values pass through to the provider without requiring discovery or catalog membership; validate bounded effort syntax at the shared boundary and let provider errors report unsupported manual choices. Codex reads per-model effort/service tiers for detected choices and adds its supported Normal (`default`) choice independently of optional advertised faster tiers. Pass `effort` and turn-local `serviceTierForTurn`: `default` explicitly requests ordinary speed, advertised tier IDs pass through exactly, and inherit omits the override without changing thread defaults. Service selections still require verified capabilities. Claude passes `--effort`. Pi identifies its current/default model and current thinking level from `get_state`, queries each catalog model's exact RPC thinking levels in a separate no-session process selected by the non-persistent `--model` runtime override, labels a default effort only for the authoritative current model, and passes `--thinking`; never use Pi's persistent `set_model` RPC for capability inspection. Both legacy omitted and explicit Pi efforts reach the provider for validation/clamping. ACP model selection remains supported, but reasoning and speed are unsupported because ACP advertises optional thought choices only after session creation and defines no standard speed category.
- Build commands without shell interpolation, bound scanner/event payloads, surface startup and negotiation diagnostics, and keep portable fixture providers synthetic.
- Keep Agent Zero CLI as the fixed `agent-zero` profile backed by the shared ACP adapter, launch `a0 acp`, and require a bounded successful `a0 acp --check` before reporting it available.

- Harness ownership is a private nonblocking OS lock on the stable OS per-user-config spynel/harness/<canonical-workspace-hash>.lock file; file presence, contents and age are never ownership evidence, and the file is never unlinked. Keep process locks off shared workspace mounts, whose file-lock semantics may be unavailable. Each provider runs behind a private same-binary guardian retaining the lock and a separate owner-lifetime pipe. Owner loss or cancellation terminates and joins the direct provider before the guardian exits; the OS releases ownership when all holders exit. Busy ownership and pending confirmed shutdown retry automatically and publish harness readiness when resolved. Provider admission does not suppress native executor crash recovery. Keep arbitrary escaped descendants and remote effects outside this direct-provider guarantee; durable task recovery still owns reconciliation, with no supervisor task replay or lease repair.
- Start execution-bearing provider subprocesses through the shared `startProvider` boundary. Keep ownership across idle replacement and admit no successor before confirmed prior Close. Retain the actual closing provider after a timeout and retry confirmation instead of permanently poisoning the supervisor. Failed replacement preserves the saved selection. Guardians hold the lock independently of providers that close inherited descriptors; a separate pipe detects owner loss without confusing ordinary provider stdin EOF with shutdown. Mark inherited guardian descriptors close-on-exec before launching the provider so arbitrary tools cannot retain private ownership. Public settings and dispatch snapshots never expose guardian descriptors.
- Give each guarded provider its own process group. On owner loss/cancellation, terminate then kill that group after bounded grace, and join the direct provider before releasing ownership. Clean up remaining group members on direct-provider exit too. Observe exit without reaping the leader until group signals finish so PID reuse cannot target unrelated processes. Escaped processes and remote effects remain outside this inherited-group boundary.

- The private `RunWorker` entry point owns a complete ordinary `Supervisor`, adapter parsers, queues and emitters under its own context. A bounded versioned bootstrap arrives through stdin, which must close before readiness; it carries a private credential and exact primary term, never secrets in arguments or environment. Startup and every socket operation recheck controller instance/token/environment, freshness and handoff under the shared election mutation lock. The private temporary directory and Unix socket are mode 0700/0600; the random worker identity and separate credential reject stale endpoints. Harness ownership remains on the existing OS-config lock and providers still run behind their existing guardians.
- Acquire that harness lock before adapter construction, including unavailable startup. An adapter startup error remains the Supervisor's explicit unavailable state while authenticated inspection and configuration stay reachable; it is not worker-start failure or provider readiness. Only an authentic confirmed-dead rendezvous permits a bounded startup wait for the existing harness lock while guardians finish cleanup; recheck exact election ownership on each attempt and release that fence between attempts. A competing live/unverified record or absent record while the lock is busy still refuses startup. Lease write failures and cancellation stop the wait, which shares the existing 30-second launch bound. Other ownership, bootstrap, cancellation and endpoint failures still stop startup. Explicit reconfiguration may recover the same worker without an admission, and controller detach/takeover retains the existing lifetime and fencing rules.
- Worker admission sequences increase monotonically across all sessions. Retries must match their original payload; retained retries return the same result and retired sequences never dispatch again. Append/sync ordered event records before replay; bound a worker to 256 retained requests, 128 MiB total journal data and 65,536 records per request, with a 32 MiB individual record ceiling. Pages contain at most 256 records and 2 MiB except one whole bounded oversized record. Protocol 13 exposes produced and committed cursors separately: reads never commit. A consumer commits only after its downstream effects are durable and deduplicated by worker ID, admission sequence and event cursor. Commit compares the expected previous prefix, never rewinds or exceeds produced events, confirms the same prefix idempotently and privately syncs its cursor before replying. Replacement controllers inspect that prefix and replay the unsettled suffix; only a fully committed terminal stream may be acknowledged and removed. Cursor persistence or partial retirement failure stops the host. The same receipts also fence replay of complete terminal journals after confirmed worker death; arbitrary downstream effects are not exactly-once. Storage/capacity failure stops the worker rather than acknowledging unrecorded events. Explicit shutdown/signals and ten minutes without an authenticated current-controller request stop/join its providers and remove its private endpoint/journals; ordinary client disconnect and election-term changes do not.
- After successful reservation, only SendNotAdmittedError permits the worker to synthesize a terminal error. For an ordinary conversation, first pass that proof and the exact original admission receipt/whole batch to the owning source callback for synced restoration. Restoration failure stops the host without acknowledging completion or exposing storage details. Matching retries repeat neither restoration nor Send. Recovery reservations are never restored. Other Send errors journal a nonterminal degraded status, retain the execution/sources/output and return unconfirmed admission; matching Send retries remain unconfirmed without another reservation or provider call. Actual provider terminal events remain authoritative, resolve prior admission uncertainty and retain useful conversation output. Deadline errors remain preserved. Journal/checkpoint failure stops the host and returns unavailable rather than unrecorded completion; downstream commit and retirement remain required. Refused workflow reservations retain their inspectable non-dispatched admission failure. A refused conversation source batch instead syncs one completed status event before its checkpoint/reply; this is a non-provider refusal, never a terminal reply or source coverage. Journal/checkpoint failure stops the worker. The existing archive consumer commits this status before retirement; reserved provider failures still require ordinary conversation effects.
- Sync a private admission checkpoint with the exact request digest and optional typed workflow claim before any reservation, then sync the owning reservation result before Send and the dispatch result before replying. Admission bytes share the journal capacity budget; checkpoint/retirement failure stops the host. The injected orchestrator reservation callback runs inside the existing exact-election fence and must not reacquire it or call worker RPCs. Inspection restores the original descriptor and counters without another reservation; matching retries reuse them, changed retries fail, and a retained workflow session or exact claim cannot be sent under a new sequence. Failed reservation remains an inspectable terminal admission without provider dispatch. These checkpoints survive controller loss through the live worker and preserve original admission identity during current-schema terminal-journal recovery; they do not prove completion of unfinished provider work.
- `OpenWorker` first reads the bounded private OS-config rendezvous beside the stable harness lock, verifies native PID/start/executable/generation through `updater`, requires the same environment/workspace, and authenticates an inspection with the current election term. - Exact-term `session` inspection returns advisory thread/activity/follow-up admission state and retained-delivery presence without sending work. Provider inactivity never proves delivery retirement. - The continuous primary binds the independent worker after service construction. The private Manager workflow/job consumer can attach and settle a matching retained claim.
