# Harness Adapter DOX

## Purpose

- Own the provider-neutral harness interface, catalog/factories, transactional supervisor, and Codex, Claude Code, Agent Zero CLI, Pi, and ACP process adapters.

## Local Contracts

- Keep application and orchestration code harness-neutral; adapters map native events into the common response and follow-up contract.
- Codex maps strictly boolean `error.willRetry: true` to nonterminal `reconnecting` status, retaining diagnostics in captured events. Only nonempty agent-message, reasoning, or plan deltas for the exact active turn restore `running`; tool output and generic activity do not establish upstream recovery. Missing/false/malformed retry flags remain errors. Serialize admission, deferred replay, live notifications, and transport failure through callback publication; publish admission first and reject another turn's late events. Transport failure also fences pending admission so a successful RPC reply cannot resurrect an exited provider.
- Resume Codex threads with `excludeTurns: true`: Codex retains its conversation context, while Spynel consumes only thread identity and its own bounded history. Any resume failure preserves the saved session and rejects dispatch instead of silently creating a replacement conversation. Keep the shared 16 MiB message bound; overflow and EOF close provider stdin as well as cancelling the subprocess so npm-launched native children receive EOF, fail pending/active work, and remain visibly unavailable through the supervisor until explicit restart or successful reconfiguration. Overflow diagnostics inspect only a bounded envelope prefix to identify a known notification or the correlated pending RPC, report unavailable metadata explicitly, and name the message-size limit and reconnect action without exposing payloads, provider IDs, arbitrary method strings, or replaying interrupted requests.
- Declare native-steer versus queued follow-up behavior explicitly, fence active executions, and invoke durable iteration reservation exactly once immediately before accepted provider delivery.
- Expose the provider-neutral new/steered/queued conversation admission classification at the same session fence so application correlation can cover consolidated terminal responses exactly.
- When an ordinary queued follow-up replaces an emitter, deliver its predecessor's continuing result followed by an explicit done-status release. This closes every request and balances application/channel activity without claiming logical completion. Orchestrator controls that preserve their emitter do not release it.
- An interruption attempt cancels not-yet-dispatched ordinary follow-ups with a terminal error per request, including every emitter in a dequeued batch. Capture the cancellation generation when removing queued work, preserve it through batching, and reject stale dispatch even if a successor turn is active. Queued controls retain their shared emitter; only the provider owns that execution's terminal event. Failure to interrupt the active provider does not restore already-cancelled queued requests.
- Order forward-looking model commits and dispatch snapshots under one supervisor fence. Never mutate an already-admitted provider turn; native steering remains part of that turn, while queued continuations and later top-level turns snapshot the newest model at their own provider-dispatch admission.
- Extend that fence to reasoning effort and service mode. Catalog metadata declares effort support for Codex, Claude, and Pi. Their model and effort values pass through to the provider without requiring discovery or catalog membership; validate bounded effort syntax at the shared boundary and let provider errors report unsupported manual choices. Codex reads per-model effort/service tiers for detected choices and adds its supported Normal (`default`) choice independently of optional advertised faster tiers. Pass `effort` and turn-local `serviceTierForTurn`: `default` explicitly requests ordinary speed, advertised tier IDs pass through exactly, and inherit omits the override without changing thread defaults. Service selections still require verified capabilities. Claude passes `--effort`. Pi identifies its current/default model and current thinking level from `get_state`, queries each catalog model's exact RPC thinking levels in a separate no-session process selected by the non-persistent `--model` runtime override, labels a default effort only for the authoritative current model, and passes `--thinking`; never use Pi's persistent `set_model` RPC for capability inspection. Both legacy omitted and explicit Pi efforts reach the provider for validation/clamping. ACP model selection remains supported, but reasoning and speed are unsupported because ACP advertises optional thought choices only after session creation and defines no standard speed category.
- Build commands without shell interpolation, bound scanner/event payloads, surface startup and negotiation diagnostics, and keep portable fixture providers synthetic.
- Keep Agent Zero CLI as the fixed `agent-zero` profile backed by the shared ACP adapter, launch `a0 acp`, and require a bounded successful `a0 acp --check` before reporting it available.

- Harness ownership is a private nonblocking OS lock on the stable OS per-user-config spynel/harness/<canonical-workspace-hash>.lock file; file presence, contents and age are never ownership evidence, and the file is never unlinked. Keep process locks off shared workspace mounts, whose file-lock semantics may be unavailable. Each provider runs behind a private same-binary guardian retaining the lock and a separate owner-lifetime pipe. Owner loss or cancellation terminates and joins the direct provider before the guardian exits; the OS releases ownership when all holders exit. Busy ownership and pending confirmed shutdown retry automatically and publish harness readiness when resolved. Provider admission does not suppress native executor crash recovery. Keep arbitrary escaped descendants and remote effects outside this direct-provider guarantee; durable task recovery still owns reconciliation, with no supervisor task replay or lease repair.
- Start execution-bearing provider subprocesses through the shared `startProvider` boundary. Keep ownership across idle replacement and admit no successor before confirmed prior Close. Retain the actual closing provider after a timeout and retry confirmation instead of permanently poisoning the supervisor. Failed replacement preserves the saved selection. Guardians hold the lock independently of providers that close inherited descriptors; a separate pipe detects owner loss without confusing ordinary provider stdin EOF with shutdown. Public settings and dispatch snapshots never expose guardian descriptors.
- Give each guarded provider its own process group. On owner loss/cancellation, terminate then kill that group after bounded grace, and join the direct provider before releasing ownership. Observe exit without reaping the leader until group signals finish so PID reuse cannot target unrelated processes. Escaped processes and remote effects remain outside this inherited-group boundary.
