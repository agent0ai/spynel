# Harness Adapter DOX

## Purpose

- Own the provider-neutral harness interface, catalog/factories, transactional supervisor, and Codex, Claude Code, Agent Zero CLI, Pi, and ACP process adapters.

## Local Contracts

- Keep application and orchestration code harness-neutral; adapters map native events into the common response and follow-up contract.
- Codex maps strictly boolean `error.willRetry: true` to nonterminal `reconnecting` status, retaining diagnostics in captured events. Only nonempty agent-message, reasoning, or plan deltas for the exact active turn restore `running`; tool output and generic activity do not establish upstream recovery. Missing/false/malformed retry flags remain errors. Serialize admission, deferred replay, live notifications, and transport failure through callback publication; publish admission first and reject another turn's late events. Transport failure also fences pending admission so a successful RPC reply cannot resurrect an exited provider.
- Resume Codex threads with `excludeTurns: true`: Codex retains its conversation context, while Spynel consumes only thread identity and its own bounded history. Any resume failure preserves the saved session and rejects dispatch instead of silently creating a replacement conversation. Keep the shared 16 MiB message bound; overflow and EOF close provider stdin as well as cancelling the subprocess so npm-launched native children receive EOF, fail pending/active work, and remain visibly unavailable through the supervisor until explicit restart or successful reconfiguration. Overflow diagnostics inspect only a bounded envelope prefix to identify a known notification or the correlated pending RPC, report unavailable metadata explicitly, and name the message-size limit and reconnect action without exposing payloads, provider IDs, arbitrary method strings, or replaying interrupted requests.
- Declare native-steer versus queued follow-up behavior explicitly, fence active executions, and invoke durable iteration reservation exactly once immediately before accepted provider delivery. NativeSteerer is non-owning: retain the current emitter without a done-status handoff; ordinary conversation steering still transfers emitter ownership.
- Expose the provider-neutral new/steered/queued conversation admission classification at the same session fence so application correlation can cover consolidated terminal responses exactly.
- When an ordinary queued follow-up replaces an emitter, deliver its predecessor's continuing result followed by an explicit done-status release. This closes every request and balances application/channel activity without claiming logical completion. Orchestrator controls that preserve their emitter do not release it.
- An interruption attempt cancels not-yet-dispatched ordinary follow-ups with a terminal error per request, including every emitter in a dequeued batch. Capture the cancellation generation when removing queued work, preserve it through batching, and reject stale dispatch even if a successor turn is active. Queued controls retain their shared emitter; only the provider owns that execution's terminal event. Failure to interrupt the active provider does not restore already-cancelled queued requests.
- Order forward-looking model commits and dispatch snapshots under one supervisor fence. Never mutate an already-admitted provider turn; native steering remains part of that turn, while queued continuations and later top-level turns snapshot the newest model at their own provider-dispatch admission.
- Extend that fence to reasoning effort and service mode. Catalog metadata declares effort support for Codex, Claude, and Pi. Their model and effort values pass through to the provider without requiring discovery or catalog membership; validate bounded effort syntax at the shared boundary and let provider errors report unsupported manual choices. Codex reads per-model effort/service tiers for detected choices and adds its supported Normal (`default`) choice independently of optional advertised faster tiers. Pass `effort` and turn-local `serviceTierForTurn`: `default` explicitly requests ordinary speed, advertised tier IDs pass through exactly, and inherit omits the override without changing thread defaults. Service selections still require verified capabilities. Claude passes `--effort`. Pi identifies its current/default model and current thinking level from `get_state`, queries each catalog model's exact RPC thinking levels in a separate no-session process selected by the non-persistent `--model` runtime override, labels a default effort only for the authoritative current model, and passes `--thinking`; never use Pi's persistent `set_model` RPC for capability inspection. Both legacy omitted and explicit Pi efforts reach the provider for validation/clamping. ACP model selection remains supported, but reasoning and speed are unsupported because ACP advertises optional thought choices only after session creation and defines no standard speed category.
- Build commands without shell interpolation, bound scanner/event payloads, surface startup and negotiation diagnostics, and keep portable fixture providers synthetic.
- Keep Agent Zero CLI as the fixed `agent-zero` profile backed by the shared ACP adapter, launch `a0 acp`, and require a bounded successful `a0 acp --check` before reporting it available.

- Harness ownership is a private nonblocking OS lock on the stable OS per-user-config spynel/harness/<canonical-workspace-hash>.lock file; file presence, contents and age are never ownership evidence, and the file is never unlinked. Keep process locks off shared workspace mounts, whose file-lock semantics may be unavailable. Each provider runs behind a private same-binary guardian retaining the lock and a separate owner-lifetime pipe. Owner loss or cancellation terminates and joins the direct provider before the guardian exits; the OS releases ownership when all holders exit. Busy ownership and pending confirmed shutdown retry automatically and publish harness readiness when resolved. Provider admission does not suppress native executor crash recovery. Keep arbitrary escaped descendants and remote effects outside this direct-provider guarantee; durable task recovery still owns reconciliation, with no supervisor task replay or lease repair.
- Start execution-bearing provider subprocesses through the shared `startProvider` boundary. Keep ownership across idle replacement and admit no successor before confirmed prior Close. Retain the actual closing provider after a timeout and retry confirmation instead of permanently poisoning the supervisor. Failed replacement preserves the saved selection. Guardians hold the lock independently of providers that close inherited descriptors; a separate pipe detects owner loss without confusing ordinary provider stdin EOF with shutdown. Mark inherited guardian descriptors close-on-exec before launching the provider so arbitrary tools cannot retain private ownership. Public settings and dispatch snapshots never expose guardian descriptors.
- Give each guarded provider its own process group. On owner loss/cancellation, terminate then kill that group after bounded grace, and join the direct provider before releasing ownership. Clean up remaining group members on direct-provider exit too. Observe exit without reaping the leader until group signals finish so PID reuse cannot target unrelated processes. Escaped processes and remote effects remain outside this inherited-group boundary.

- The private `RunWorker` entry point owns a complete ordinary `Supervisor`, adapter parsers, queues and emitters under its own context. A bounded versioned bootstrap arrives through stdin, which must close before readiness; it carries a private credential and exact primary term, never secrets in arguments or environment. Startup and every socket operation recheck controller instance/token/environment, freshness and handoff under the shared election mutation lock. The private temporary directory and Unix socket are mode 0700/0600; the random worker identity and separate credential reject stale endpoints. Harness ownership remains on the existing OS-config lock and providers still run behind their existing guardians.
- Worker admission sequences increase monotonically across all sessions. Retries must match their original payload; retained retries return the same result and retired sequences never dispatch again. Append/sync ordered event records before replay; bound a worker to 256 retained requests, 128 MiB total journal data and 65,536 records per request, with a 32 MiB individual record ceiling. Pages contain at most 256 records and 2 MiB except one whole bounded oversized record. Protocol 9 exposes produced and committed cursors separately: reads never commit. A consumer commits only after its downstream effects are durable and deduplicated by worker ID, admission sequence and event cursor. Commit compares the expected previous prefix, never rewinds or exceeds produced events, confirms the same prefix idempotently and privately syncs its cursor before replying. Replacement controllers inspect that prefix and replay the unsettled suffix; only a fully committed terminal stream may be acknowledged and removed. Cursor persistence or partial retirement failure stops the host. This is a surviving-worker consumer contract, not cross-worker journal recovery or exactly-once downstream effects. Storage/capacity failure stops the worker rather than acknowledging unrecorded events. Explicit shutdown/signals and ten minutes without an authenticated current-controller request stop/join its providers and remove its private endpoint/journals; ordinary client disconnect and election-term changes do not.
- Sync a private admission checkpoint with the exact request digest and optional typed workflow claim before any reservation, then sync the owning reservation result before Send and the dispatch result before replying. Admission bytes share the journal capacity budget; checkpoint/retirement failure stops the host. The injected orchestrator reservation callback runs inside the existing exact-election fence and must not reacquire it or call worker RPCs. Inspection restores the original descriptor and counters without another reservation; matching retries reuse them, changed retries fail, and a retained workflow session or exact claim cannot be sent under a new sequence. Failed reservation remains an inspectable terminal admission without provider dispatch. These checkpoints survive controller loss through the live worker; they are not cross-worker journal recovery, application job restoration or ordinary dispatch selection.
- `OpenWorker` first reads the bounded private OS-config rendezvous beside the stable harness lock, verifies native PID/start/executable/generation through `updater`, requires the same environment/workspace/current configuration, and authenticates an inspection with the current election term. Unknown identity, absent registration for a live process, unsafe credentials/socket permissions, inaccessible live endpoints and changed configuration fail closed. Only absent rendezvous or confirmed dead/zombie workers permit detached same-binary launch; the existing harness lock prevents competing provider starts. Bootstrap uses stdin, with no inherited controller stdio or terminal group. The worker publishes/removes only its own credential record; another live/unverified worker's record is never overwritten. Startup cancellation detaches instead of killing a worker another opener may already own.
- `WorkerClient.Close` only closes idle connections. Every call verifies native identity, carries the exact worker/controller identities, bounds request/response bytes and never automatically repeats an admission. Client connection/discovery never invokes Send, retires a journal or reserves a provider turn. Callers retain exact admission sequence/payload and consumed cursors; the protocol alone does not settle downstream effects.
- Exact-term `session` inspection returns advisory thread/activity/follow-up admission state without sending work. `reset` delegates to the existing supervisor/adapter only after every retained execution for that key is consumed and retired; it cannot discard pending terminal delivery. Inspection is not an admission reservation. No controller election-lock callback may enclose these RPCs.
- `WorkerClient.Consume` applies one bounded page after the committed prefix. It rechecks native identity and exact controller ownership around each downstream callback, releases that fence before the commit RPC, and propagates callback/commit failures without retiring the execution. Callbacks must be short, persist and deduplicate their effects by the supplied worker/sequence/cursor receipt, and must not call worker RPCs or reacquire election ownership. A page may replay after a failure or lost reply; owning receipts make that safe. The history store has a synced single-record effect/receipt primitive, exercised across actual controller exits. The private Manager workflow path now uses a synced job-archive prefix receipt; ordinary heartbeat/notification consumers now use the same receipts; conversation consumers still need integration. No admission or provider-turn reservation occurs during consumption.
- The independent worker is not selected by `buildService` yet. The private Manager workflow/job consumer can attach and settle a matching retained claim. Production conversation/history consumers, normal composition and coordinated restart/update/stop integration remain required before enabling it. Discovery requires the current committed configuration and confirms its digest through authenticated inspection; an earlier rendezvous snapshot cannot authorize stale settings. Never substitute an `inspect`/`events` attachment with a new `send` or provider-iteration reservation, or invoke this cross-process client from inside a controller election-lock callback.


- RunOwned provides the same exact native/controller fence as Consume for short local mutations such as workflow scans and job admission. Callbacks cannot invoke worker RPCs or reacquire election ownership. RPC inspection precedes the fence; only the private manager currently binds this workflow path.

- Ordinary heartbeat/notification admissions retain a separate opaque ID, role, source-file reference and original bounded deadline. Validate metadata before admission, forbid overlapping retained agent sessions/IDs, and include the descriptor in retry identity and synced checkpoints. The original deadline also bounds initial Send; the worker attempts deadline interruption independently of controller lifetime, checkpoints timeout and journals interruption failure without inventing provider release. Failed interruption remains fenced until explicit control or ordinary worker cleanup; no automatic re-dispatch or deadline extension occurs. These are ordinary harness lifetimes, never notification decisions, delivery results or reminder policy.

- Private workflow controls bind the retained sequence and exact stable claim, validating its current manager owner before admission. Keep initial delivery under the request election fence, and queued preparation/reservation/delivery under that same admitting term through RunContinuation; acquire worker-operation/election locks before the supervisor session lock. Never reacquire the election fence inside callbacks. Reuse the bounded Supervisor queue, deduplication and single continuation. A refused continuation releases the original provider terminal; an error after actual admission must not fabricate release. Sync each new reservation before delivery. Sync accepted cancellation intent before interruption; restore only a rejected serialized attempt, and fail closed on checkpoint failure. Retain the flag through attachment and terminal consumption.

- Native worker control acknowledgement waits have a five-second server-owned context, independent of the retained execution and queued continuation lifetime. Timeout releases the operation/election fence, preserves ambiguous-delivery deduplication and never cancels or redispatches the provider turn.
- Every interactive provider stdin uses the shared five-second native pipe-write deadline, including protocol replies and initial prompts. A failed/partial write closes that input so another request cannot complete or corrupt its frame; return the error without retrying or claiming provider release. The existing guardian retains process cleanup ownership. This bounds pipe backpressure separately from acknowledgement and provider execution lifetimes.

- Protocol 9 retains exact-term configuration and adds optional bounded private canonical YAML with expected canonical/runtime digests. The config-owned callback validates schema, canonical path and exact runtime selection, then saves/reloads inside the inference dispatch fence before rendezvous publication. Restore original bytes on persistence/publication failure; failed restoration stops the worker. Structural replacement retains its existing idle/consumed-delivery fence and runtime rollback. Applied retries confirm the exact saved target without another provider admission. Model discovery runs through the owning adapter with a ten-second context. Authenticated inspection returns current runtime selection/digest; WorkerClient.Info remains its discovery snapshot. Canonical YAML may contain credentials and never belongs in logs or evidence. Normal production composition/conversation/coordinated-lifecycle integration remains unfinished.


- Protocol 9 privately retains an immutable WorkerConversation descriptor with one logical execution and up to 1024 sorted unique source identities. Admission and replay share its validator; request keys and role exclusivity are checked before Send, matching retries retain the original descriptor, and another admission for that retained session fails closed. The worker retains streamed partial text and includes it only with a terminal error; request-only classification is captured beside the event rather than queried by an election-fenced consumer. Descriptor and error-prefix bytes share existing checkpoint/journal limits. Normal source reservation, conversation follow-ups, automatic attachment and production selection remain unconnected; callers must not infer their safety from this single-batch primitive.
