# Internal Runtime DOX

## Purpose

- Own the provider-neutral runtime, channel adapters, harnesses, durable state, extension hooks, workspace initialization, and markdown orchestration.

## Package Ownership

- `app` composes screens, live settings, channel and harness supervisors, histories, commands, hooks, orchestration, captured runtime logs, startup registration, conversation branching, and the active agent-job registry.
- `channel` owns the common transport contract, hot-reload lifecycle supervision, and TUI, Telegram, and WhatsApp adapters.
- `cli` owns public command parsing and process lifecycle.
- `config` owns `spynel.yaml` defaults, loading, path resolution, and validation.
- `core` owns messages, responses, and stable cross-package value types.
- `extensions` owns executable hook discovery and Git installation.
- `fsx` owns cross-platform atomic file replacement.
- `history` owns independent append-oriented channel history, explicit per-conversation clearing, bounded context rendering, disk-backed discovery, and point-in-time branching.
- `markdown` owns GitHub-flavored Markdown rendering for ANSI terminals, including standard OSC 8 hyperlinks for explicit absolute-file and URI links, and conversion to Telegram HTML or WhatsApp-native formatting.
- `media` owns bounded streamed attachment storage and serialized, disk-backed local Whisper transcription.
- `orchestrator` owns route scanning, markdown claims, leases, stale recovery, and dispatch.
- `harness` owns the harness interface, transactional runtime supervisor, Codex app-server implementation, and Claude Code print-mode implementation.
- `shortid` owns compact eight-alphanumeric-character rendering of opaque IDs for human-facing output; full identifiers remain authoritative internally.
- `startup` owns reversible, workspace-specific systemd, launchd, and Windows Task Scheduler registration.
- `workspace` owns initialized filesystem structure and embedded, user-overridable templates.

## Local Contracts

- Avoid package cycles by keeping cross-boundary values in `core` and interfaces beside their consumers.
- Configuration changes from forms and commands share the typed `config.Setting` catalog, are validated as a complete transaction, persist through an atomic `0600` replacement, and publish only the newest snapshot. Never place secret setting values in status output, framework replies, or durable conversation history. Telegram fails closed: it cannot be enabled with an empty allowed-users whitelist, cannot clear that whitelist while enabled, and links the whitelist description and wizard to the third-party `@userinfobot` helper for discovering numeric user IDs.
- Persist `harness.name`, optional `harness.model`, and `harness.sandbox` for coding-harness selection and permissions. New workspace initialization detects `codex` first and `claude` second from `PATH`; select the first available automatically or open the shared harness chooser when neither is found. Default `harness.sandbox` to `danger-full-access`, expose the validated `danger-full-access`, `workspace-write`, and `read-only` choices in `/config`, and apply changes transactionally to an idle harness. Derive the executable, workspace directory, approval policy, network flag, and default effort internally—never expose manual harness-path controls. Read legacy `recipient:` YAML and session files without emitting that terminology for new state.
- Interactive `spynel init` and confirmation from the uninitialized-directory screen continue into harness setup/welcome/chat in the same process. `spynel init --no-start` is the non-interactive/scripted initialization contract.
- A TUI form screen is a transport-neutral `core.Screen` rendered instead of chat. Form controls use Up/Down or Tab/Shift+Tab navigation, edit text in place, cycle choices with Space/Enter, save atomically with Ctrl+S, and return to the preserved chat with Escape. Text-only channels configure the same keys through shared commands. Every Telegram and WhatsApp form and wizard begins with its live connection state and available detail or error text, ahead of banners, pairing content, instructions, and settings. Telegram and WhatsApp put a setup-wizard action first, followed by exactly one blank row before the essential settings. Wizards provide one concise step at a time, Back/Continue/Cancel actions, Markdown-rendered official hyperlinks, hidden in-memory state that is neither rendered nor keyboard-selected, and a single validated essential-settings save; place exactly one blank row between a wizard's editable control and its contiguous navigation-action group. WhatsApp enables its channel before waiting for the live pairing QR. The pairing step starts at the top so the complete QR is reachable and PageUp/PageDown moves through QR content without changing the selected action. After the wizard, Telegram presents token, allowed users, and enabled; WhatsApp presents mode, allowed numbers, and enabled. Every other channel control starts hidden behind the shared advanced-settings disclosure, remains keyboard-navigable when expanded, and retains edits when collapsed before save. Put one blank row between the essential controls and the Show/Hide advanced disclosure, and one between the expanded Hide advanced disclosure and its first advanced control.
- Form text and password controls own their editing keys after focus: Space inserts a literal space, Left/Right moves the in-field cursor, Home/End jumps to an edge, and Backspace/Delete edits relative to that cursor. The cursor position is retained independently for every control; these keys keep their choice-cycling meaning only on toggle/select controls.
- Persist state atomically with a temporary sibling plus rename.
- Treat bot tokens, phone numbers, WhatsApp credentials, message histories, and harness thread IDs as sensitive.
- Sanitize every external conversation identifier before using it in a path.
- Extension hooks execute only from explicitly installed project repositories and receive JSON over stdin/stdout.
- Generated workspace instructions must explain every configured route, status transition, front-matter requirement, and agent side effect.
- The TUI composer starts at one visible row, grows with wrapped or explicit lines up to ten rows, sends with Enter, and inserts a newline only with Shift+Enter; Alt+Enter is not a newline binding.
- Composer wrapping reveals each successive row in place through row ten; only content beyond the ten-row cap scrolls, one visual row at a time. Repeated destructive edits at the end of an over-height composer keep the cursor anchored to its bottom row and reveal preceding text above it. Typing and composer/menu resizing preserve the chat viewport's exact history offset.
- Render the composer placeholder as muted italic text and keep the active input line styled identically to ordinary input text, without cursor-line or placeholder highlighting in either focused or blurred states; the cursor block alone indicates position.
- Ctrl+C clears non-empty composer text and all transient input UI such as the slash picker and paste tokens; Ctrl+C exits only when the composer is already empty after that reset.
- While a harness turn is active, render the compact three-dot Braille spinner as a cursor-like placeholder immediately after the last visible response character, with no intervening label or space; before any response text it appears directly after `Spy `. Keep it visible and animated during streaming, then remove it on the final response or error. Use the cycle `⠋`, `⠙`, `⠸`, `⠴`, `⠦`, `⠇`, keep the two-cell Spynel logo exclusive to the header, and preserve the history scroll offset while either animation ticks.
- Preserve every agent-message item produced during one harness turn, displaying and persisting them in order with a newline separator between items. A final event that contains only the last item must not replace prior streamed items in the TUI.
- When the user sends a framework slash command during an active harness turn, commit the currently streamed assistant text in place without its spinner, render the user command and local response normally, then render a new `Spy` activity entry for subsequent harness output. Local framework finals must not end harness activity or stop its animation, and the eventual harness final must append only output not already committed before the intervention.
- Use separator-free minimal chat prefixes `You ` and `Spy ` so user and agent content starts at column four. Indent every explicit or wrapped continuation line to that same content column. Render only the `You` label in a restrained blue accent so user turns are easy to identify without coloring its spacing or message body.
- Typing `/` at the start of the TUI composer opens the canonical slash-command picker; Up/Down navigates, Tab inserts the selection, and Enter sends it immediately. Title the picker only `Commands`; show its bindings in the footer instead of duplicating them in the picker border.
- Command-picker rows are flush-left with no selection marker or reserved left padding; selection is communicated by highlight color alone.
- TUI Up/Down belongs only to the composer and PageUp/PageDown belongs only to chat history. Keep application mouse reporting disabled so ordinary terminal drag selection and copying work without a modifier; ignore any stale structured mouse events and defensively discard complete or fragmented SGR click, drag, release, and wheel reports so protocol bytes can never enter the composer, while preserving intentional pasted text. Mouse-wheel behavior remains terminal-native rather than being captured by the TUI.
- Invalidate the TUI renderer cache every ten seconds so terminal-owned screen clears self-heal without changing the chat-history offset. Ctrl+L requests the same full-frame redraw immediately, and sending a message also requests one; these redraws must not erase composer text or application state. Keep the Ctrl+L fallback out of the footer hints.
- Reserve the TUI header for status icons and runtime data: the two-cell Spynel state logo, current title and operational state, compact Telegram (`TG`) and WhatsApp (`WA`) connection symbols, `N jobs`, and `N logs`. Inset the header by exactly one terminal column, render the logo and title together in the pink accent, and render every remaining item in the same muted blue foreground as the footer, without a separate jobs icon or spinner. Show `○○` before any response, animate active harness turns through `◉◉`, `◑◉`, `○◉`, `○◑`, `○○`, `◐○`, `◉○`, `◉◐`, `◉◉`, and show `◉◉` when the latest response is complete.
- Reserve the TUI footer exclusively for one context-sensitive set of control hints, inset it by exactly one terminal column, and place it on the terminal's final row with no blank line below it. The command-picker hints replace the ordinary composer hints rather than being prepended or combined with status text.
- Runtime output from the harness, orchestrator, and background channels must be captured above the alternate-screen TUI rather than written directly to its terminal. Retain at most 4,096 process-local entries and 4,096 runes per entry. `/log` shows the newest 20 captured entries, `/log page <number>` pages backward with page 1 newest, `/log search <text>` performs a case-insensitive bounded search, and `/log clear` removes captured entries and pending partial output. The header shows the live `N logs` count, and all log options work through every channel.
- Track active chat and orchestrator harness executions as process-local jobs with monotonically increasing job numbers. The header shows the plain `N jobs` count, `/jobs` lists them, and `/job kill <number>` interrupts the exact owning harness session.
- Shared `/status` output must expose the TUI's relevant runtime indicators to every channel: title, Telegram and WhatsApp connection states, log and job counts, harness/model/sandbox/thread/turn state, and orchestrator activity. Display opaque thread and similar GUID-like identifiers as eight alphanumeric characters without shortening their persisted or protocol values.
- `/title <name>` works through every channel, atomically persists the TUI window title below the configured state directory, and updates a running TUI.
- Every canonical application slash command is handled through the shared application service for TUI, Telegram, and WhatsApp. `/quit` remains TUI-scoped and remote invocations must explain that without stopping the server.
- `/restart` is process-wide on every channel. Persist and emit its acknowledgment before publishing a coalesced restart request; the CLI must allow that response to render, cancel the runtime, close the harness, restore the TUI terminal, and relaunch the current executable in the same working directory. Preserve the active server arguments, except that a TUI reached through `spynel init` must relaunch as `serve --tui --config <initialized-file>` so initialization is not repeated. Use in-place replacement on Unix and an inherited-stdio successor on Windows so saved configuration, histories, and harness session mappings remain usable after reconnecting.
- `/config`, `/telegram`, and `/whatsapp` open typed form screens in the TUI and expose `get`/`set` command equivalents elsewhere. Main configuration begins with dedicated harness/model actions plus agent filesystem access, context, and startup essentials, then hides task-management, extension, speech, channel, and storage fields behind Advanced settings. Harness/model selectors opened from config are nested screens: Enter applies and returns to the exact preserved config state, while Escape returns without applying; directly invoked selectors still return to chat. `/telegram on|off` and `/whatsapp on|off` are concise toggles. Telegram must refuse changes to Telegram itself and WhatsApp must refuse changes to WhatsApp itself; either channel may safely configure the other.
- Harness, context, title, speech, channel, and startup scalar changes have their documented live/transactional effects. TUI-default, orchestrator, and extension scalar controls persist through the same catalog but are explicitly restart-bound; structured route arrays remain YAML-edited.
- Persisted channel changes are live: the channel supervisor cancels only the stale instance, starts the replacement, isolates transport failure from the TUI and orchestrator, and retries enabled failed transports on a bounded interval.
- `/harness` switches between built-in Codex and Claude Code implementations only while the current harness is idle. It shows live detected/not-detected state, persists a missing built-in choice only when no harness is running, remains on installation guidance for that choice, and retries it when selected again. `/model` uses the selected harness's catalog when available and accepts an exact model identifier from every channel. Their bare TUI commands render one action row per available choice, initially focus the current choice, navigate with Up/Down or Tab/Shift+Tab, and apply the highlighted choice immediately with Space/Enter; these selection lists never require Ctrl+S.
- Accept Telegram's group-chat `/command@botname` form as the same shared slash command while preserving its arguments.
- `/stop` requests provider-level interruption of the active harness turn for only the issuing channel/conversation and reports clearly when no execution is active.
- Bare `/help` is a concise topic index; `/help <topic>` routes to focused built-in guidance, and the canonical slash picker exposes the topic commands.
- Enabled channel adapters report connecting, connected, and error lifecycle changes to the TUI; disabled adapters remain visibly unconfigured. After Telegram's `getMe` succeeds, its `/telegram` status section shows the validated `@username` as a clickable `https://t.me/<username>` target so the user can open the bot conversation directly.
- `spynel serve` remains alive when the selected harness is unavailable so remote status/configuration and deterministic task management stay reachable; harness-dependent dispatch waits for a successful runtime reconfiguration.
- Compact bracketed-paste bodies of at least 1,000 characters into atomic display tokens while preserving their full dispatch text. Copy pasted local file paths into the configured state directory's `attachments` folder and use atomic attachment-link tokens.
- Stream Telegram and WhatsApp media into channel-specific attachment directories with private permissions and a configured byte limit; never buffer an unbounded remote body in memory. Stable remote conversation keys use `TG-<user-id>`/`TG-group-<chat-id>` and `WA-<number>`/`WA-group-<group-id>` so restarts reuse the same history and harness session. Channel configuration must not inject project bindings or extra per-channel instructions into harness prompts.
- For every accepted Telegram or WhatsApp message, start the native typing/composing indicator before attachment download or voice transcription, refresh it every four seconds through asynchronous harness execution, and stop it only after the terminal response/error is delivered or the channel context ends. Reference-count activity per chat so an overlapping message or framework command cannot stop the indicator for an agent turn that is still running; WhatsApp sends `paused` only after the final reference ends.
- Enable speech transcription with the multilingual `small` Whisper model in fresh workspaces. Preserve the original voice attachment and prepend an explicit generated-transcription label. Use one process-wide transcription worker, normalize and split on disk with configured duration/chunk limits, process one chunk at a time, cap transcript output, and keep failures visible to the harness without dropping the attachment path. When the default `whisper-cli` is absent on a supported platform, download a pinned official whisper.cpp runtime, verify its SHA-256 digest before extracting it into the private reusable model cache, and continue to honor an explicitly configured executable without provisioning.
- Chat history, the composer, and the command picker keep the regular panel-border color on the right edge and on every inactive scrollbar-track cell. Once scrolling is possible, only a proportional pink wide `┃` thumb differs from that border; the scrollbar remains in the border column rather than consuming interior space.
- Render agent Markdown in the TUI, remove renderer-added trailing line padding before applying the chat hanging-indent wrap so one Markdown paragraph gap remains one blank row, and remove blank rendered rows immediately before and after code blocks while preserving intentional blank lines inside code. Preserve explicit absolute-file and URI destinations as clickable terminal hyperlinks without guessing a base for relative paths, and translate Markdown into the supported native formatting subset before sending through Telegram or WhatsApp with the same compact code-block boundaries.
- The TUI restores only a fixed display tail of durable `tui/local` history at startup and retains at most 500 entries/500,000 runes in its live display, with an explicit omission notice while the complete JSONL remains on disk. The once-per-workspace welcome uses the six-row block `SPYNEL` logo in pink and non-interactive `/help`, `/config`, `/telegram`, and `/whatsapp` guidance as a non-persisted banner at the top of the scrollable chat viewport; it never replaces chat or shows buttons, `/welcome` restores and focuses its top, and `/clear` removes it without reopening onboarding. `/resume` discovers conversations from disk without retaining transcript bodies, copies the selected conversation to an independent TUI branch, and loads only a fixed display tail; the source conversation remains unchanged. `/clear` removes the current conversation's persisted history and visible transcript, discards its inactive harness session so the next message starts a fresh thread, and leaves neither the command nor acknowledgment in history. If the harness session cannot be reset, preserve the conversation history and report the failure.
- Harness prompt context reads backward from append-only JSONL on demand and stops at both `workspace.history_max_messages` and `workspace.history_char_limit`; it must not load an unbounded conversation merely to produce a bounded prompt.
- The automatic-startup toggle is a transactional configuration side effect. Register one workspace-specific background service for `spynel serve --config <absolute-path>` on systemd, launchd, or Windows Task Scheduler; a registration failure must roll configuration and harness changes back.
