# Internal Runtime DOX

## Purpose

- Own the provider-neutral runtime, channel adapters, harnesses, durable state, extension hooks, workspace initialization, and markdown orchestration.

## Package Ownership

- `app` composes screens, live settings, channel and harness supervisors, histories, commands, hooks, orchestration, captured runtime logs, startup registration, conversation branching, and the active agent-job registry. Jobs retain one bounded race-safe structured execution snapshot; live execution state, workflow phase, durable outcome, and evidence-based health remain distinct. Health uses structured lifecycle or lease evidence only; elapsed text silence never implies a stall, and `stalled` requires an explicit provider signal.
- `agentdocs` owns curated offline behavior topics, stable references, deterministic bounded pagination/search, versioned structured output, prompt guidance, and concise `/help` topic metadata. It never reads workspace or runtime state.
- `channel` owns the common transport contract, hot-reload lifecycle supervision, and TUI, Telegram, and WhatsApp adapters. The TUI owns a narrowly scoped MIT-licensed Bubbles v0.21 textarea derivative because the upstream private wrapper splits fitting extended graphemes; keep its editor behavior aligned with that dependency while preserving grapheme-atomic wrapping, navigation, deletion, and character transposition.
- `cli` owns public command parsing and process lifecycle.
- `config` owns `spynel.yaml` defaults, loading, path resolution, and validation.
- `core` owns messages, responses, stable cross-package value types, and the shared compact count formatter used by constrained status indicators.
- `extensions` owns executable hook discovery and Git installation.
- `fsx` owns cross-platform atomic file replacement.
- `history` owns independent append-oriented channel history, explicit per-conversation clearing, bounded context rendering, disk-backed discovery and latest-conversation selection, and point-in-time branching into a requested target channel.
- `instance` owns cross-platform workspace-server election, lock-free discovery of atomically published authenticated rendezvous records, five-second renewal, 30-second stale detection, fenced stale takeover, and expiring target-specific handoff.
- `localapi` owns the private authenticated loopback contract through which every TUI and plain CLI client identifies its caller instance, reaches the elected application service, streams messages, obtains typed status, and observes bounded shared state.
- `markdown` owns GitHub-flavored Markdown rendering for ANSI terminals, including standard OSC 8 hyperlinks for explicit absolute-file and URI links, and conversion to Telegram HTML or WhatsApp-native formatting.
- `media` owns bounded streamed attachment storage, validated outbound file directives, serialized local Parakeet transcription through miniaudio/Ogg-Opus/sherpa-onnx, and the coordinated versioned per-user cache for automatically managed speech models.
- `orchestrator` owns typed task review policy, task implementation/review and goal planning/review scanning, task-goal round linkage, atomic Markdown claims, phase leases, orphan/stale recovery, transition enforcement, goal review gating, waiting wakeups, the primary-owned semantic workflow heartbeat, and durable notification triage, action requests, reminders, and outbox delivery.
- `harness` owns the harness interface and optional follow-up capability, the centralized built-in catalog/factories, transactional runtime supervisor, Codex app-server implementation, Claude Code streaming print-mode implementation, startup/earliest-negotiation capability diagnostics, and version-labelled portable test-binary provider fixtures for deterministic cross-platform lifecycle and protocol-variant contracts.
- `shortid` owns compact eight-alphanumeric-character rendering of opaque IDs for human-facing output; full identifiers remain authoritative internally.
- `startup` owns reversible, workspace-specific systemd, launchd, and Windows Task Scheduler registration.
- `theme` owns validated, file-backed semantic color palettes and built-in fallback colors.
- `updater` owns npm-install detection, ten-second registry checks, semantic application-version state, and retry-safe compiled-in/extension migration transitions.
- `workspace` owns initialized filesystem structure and embedded, user-overridable templates.

## Local Contracts

- Avoid package cycles by keeping cross-boundary values in `core` and interfaces beside their consumers.
- Configuration changes from forms and commands share the typed `config.Setting` catalog, are validated as a complete transaction, persist through an atomic `0600` replacement, and publish only the newest snapshot. Never place secret setting values in status output, framework replies, or durable conversation history. Telegram and WhatsApp fail closed: neither can be enabled with an empty sender whitelist, neither can clear that whitelist while enabled, and each adapter rejects all senders and reports a connection error if started without one. Enabled Telegram webhook mode additionally requires header-secret verification, and connection status must never expose its public URL or per-token path. Normalize WhatsApp allow-list comparisons to canonical international digits so `+`, `00`, spaces, and punctuation are equivalent; in self-chat mode resolve an incoming LID to the paired phone-number identity before authorization and conversation keying. Telegram links the whitelist description and wizard to the third-party `@userinfobot` helper for discovering numeric user IDs.
- WhatsApp socket reachability before device linking is pairing readiness, not a connected channel. Report `connecting` with pairing detail until the credential store has an authenticated device ID; only a paired connection may report `connected`. A connected status may expose the validated phone-number JID as `+<number>` with its official `https://wa.me/<number>` link in the TUI WhatsApp status section; never expose opaque LIDs or non-phone JIDs as account identities. Never expose QR render data on the general WhatsApp settings screen: retain it only for the pairing wizard's dedicated fullscreen QR action.
- Identify new WhatsApp QR-linked devices as `Spynel` with desktop companion metadata and an Electron QR client type instead of whatsmeow's generic unknown-device defaults. Keep phone-number code pairing on a server-accepted browser/OS display name because WhatsApp rejects arbitrary values there. Derive the executable, workspace directory, approval policy, network flag, and default effort internally—never expose manual harness-path controls. Read legacy `recipient:` YAML and session files without emitting that terminology for new state.
- Interactive `spynel init` and confirmation from the uninitialized-directory screen continue into harness setup/welcome/chat in the same process. `spynel init --no-start` is the non-interactive/scripted initialization contract.
- `spynel send` and its `message` alias use a named durable `cli` history/harness session through the elected application service when one is running, or a one-shot local service otherwise; neither starts continuous orchestration. Accept bounded stdin, repeatable private attachment copies, response-delta streaming, and NDJSON event output. TUI-only themes, titles, onboarding, ownership promotion, resume screens, and process exit remain excluded.

Perform routine bounded inspection without narrating tool steps or announcing intended checks. Ordinary question, status, and delegation turns emit exactly one brief, natural, outcome-first result with no preamble or progress messages. Routine confirmations omit internal files, local links, paths, IDs, metadata, lifecycle details, verification plans, and orchestration mechanics; explicit file/detail requests and dedicated status/job/log/document diagnostics remain precise. Telegram and WhatsApp routine confirmations never contain local-path Markdown links. An exact blocker, security implication, destructive effect, failure, or required user decision remains visible and is itself the final result when safe completion is impossible.
