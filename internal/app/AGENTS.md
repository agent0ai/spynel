# Application Service DOX

## Purpose

- Compose the provider-neutral application service used by channels, local API clients, CLI commands, configuration screens, and background orchestration.

## Local Contracts

- Keep channel/harness supervisors, histories, commands, hooks, configuration, startup registration, conversations, runtime logs, durable-work lists, and agent jobs behind the shared service boundary.
- Shared status carries the serving process's startup version from `Updates.CurrentVersion` in `StatusSnapshot.Version`; render exactly one Version row between title and the adjacent instance IDs. Preserve build metadata verbatim, including `dev`; absent metadata remains empty in JSON and displays `not available`, never an inferred installed/latest version.
- Acknowledge Telegram's `/start` with exactly `Spynel is running.` through ordinary message admission and the persisted local-reply path, without invoking a harness. Accept the usual Telegram bot mention and optional payload, keep this platform acknowledgment Telegram-only, and omit it from the slash-command catalog, TUI picker, and help.
- Configuration’s single autostart action, selected by native registration inspection on opening, and text-command equivalents use the same save/reload and startup-manager boundary. Revalidate every explicit request, including unchanged retries; reject an unavailable manager and return redacted native errors or explicit verified registration/removal. Configuration set failures propagate through the ordinary application error boundary so automation receives failure rather than a successful final containing error prose. Preserve unrelated form edits. Complete native registration before saving settings, leaving disk and published settings unchanged on native failure; restore the previously observed native enabled state if subsequent configuration persistence fails. Treat `startup.enabled` and the status projection as saved preference only, never observed OS registration or process health.
- Allocate each admitted job a durable workspace-local number from 1 through 9999 under a cross-process lock and atomically replaced counter, wrapping from 9999 to 1. Fail admission before provider dispatch when the counter or initial archive cannot be persisted; never substitute a process-local public number. Preserve the number through recovery and archival, but reopen an archived workflow job only for the same durable work ID, job kind, workflow phase, and phase claim attempt after acquiring its nonblocking cross-process ownership lock; a still-owned matching archive is an overlapping execution and must receive a new number, generation, and private identity. Later phases and attempts are also distinct jobs. After reuse, numeric lookup and the public live listing select only the newest generation; admitting or finishing an older recovered generation never shadows, removes, or exposes it in place of a newer generation. Private collision-proof archive identities and process-local execution handles keep older live or retained records isolated. Persist bounded ordered redacted event output as atomically readable snapshots, compatibly read legacy `live_alias` archives, and keep archive text inspection-only so it cannot influence workflow state.
- Treat successful channel or loopback admission as workspace-operator authorization for global runtime jobs and durable task/goal inspection. Do not add conversation, creation-channel, or notification-origin filtering inside job list, inspection, message, ping, kill, or workflow-list handlers; keep public projections bounded and free of conversation identifiers and prompt text.
- Keep `/new` as a durable TUI conversation-identity switch with the ordinary welcome screen, and route `/trigger` and manual/automatic cleanup through shared scheduler and retention boundaries rather than command-specific workers. Protect every conversation leased by an authenticated live TUI; serialize startup registration and resume branch creation-through-registration with cleanup through history deletion, retain prior identities briefly across screen switches for cleanup only, record the selected identity explicitly even when registrations share a timestamp, expire crashed-client leases before cleanup eligibility, and fence cleanup for one lease duration after owner acquisition so live clients can renew into the replacement owner's registry.
- Protect shared state and job snapshots for concurrent readers; distinguish execution state, workflow phase, durable outcome, and evidence-based health. Text silence alone is never a stall signal.
- Project the orchestrator's bounded authoritative nonterminal task/goal census and its bounded diagnostics into shared TUI state; do not derive durable work from jobs or histories.
- Project `RuntimeStatus.LiveJobs` from the full process-local job registry regardless of channel, kind, or conversation; registered cleanup records remain in `Jobs` but do not manufacture running activity. Starting, running, reconnecting, recovering, degraded, and audit executions are live; terminal, cancelling, finishing, error, and explicitly stalled records are not.
- A continuing conversation final/error completes only one provider response, not the logical queued execution. Preserve its live job state across that handoff; only a non-continuing provider terminal may mark it finishing/error and end the job. Keep request-only cancellation and runtime terminal/cancellation fences intact.
- A failed conversation send settles only that admission while the shared harness execution remains active. Roll back its source reservation and activity, retain the original job's execution state and failure diagnostic, and mark the job error/end it only when no execution remains active.
- Reserve cancellation before interrupting so synchronous provider termination is captured. Count concurrent reservations by stable job identity, and restore runtime/archive plus durable control state only when every matching request failed; one failed request must never undo another accepted cancellation. After acceptance, retain the cancelling job and archive until the provider emits a terminal event so that event remains inspectable; use a bounded grace fallback for providers that never release, and stop any application-owned conversation activity before that fallback retires the job.
- File-lock implementations remain platform-specific, captured logs remain bounded, and configuration changes validate, save, reload the canonical file into shared memory, then invoke only required cached-runtime hooks. Model persistence and harness dispatch admission share one commit fence so no post-commit dispatch observes the previous model; harness implementation and sandbox replacement remain idle-only.
- Harness replacement errors preserve disk/published settings but may leave the runtime unavailable after its prior provider has stopped. Propagate the shared supervisor's unconfirmed-shutdown refusal; rollback or later settings changes cannot bypass its retained ownership fence.
- Apply that same commit fence to reasoning effort and service mode. Model and supported-harness effort selectors end with Custom, using ordinary text controls and a final atomic save; cancellation preserves the parent configuration's unsaved edits. Discovery failure still exposes default and custom choices. Explicit model/effort settings bypass catalog membership checks, including commands and YAML; clear invalidated stored properties on model/harness changes unless an effort is explicitly supplied. Service modes and unsupported harness features remain validated.
- Notification-agent jobs are ordinary asynchronous harness jobs started directly from qualifying task transitions. The agent receives the task and ordinary CLI guidance, owns the decision, and edits task progress itself; application code never interprets provider output or writes a notification result.
- The shared notify API accepts exactly one of an explicit origin or recent-authorized routing. Recent routing uses bounded durable latest-user activity and live authorization, never returns the resolved recipient, and fails closed on multiple remote users, tied activity, groups, revocation, unknown conversations, or missing activity. Keep it a minimal resolver feeding ordinary outbox delivery; reminder policy and progress recording belong to the heartbeat agent, never application state or orchestration.
- Parse remote notification directives through `media.ParseOutbound` under the live attachment limit before any send, route cleaned text and validated attachments through the proactive delivery contract, and commit sent history only after the adapter succeeds. CLI/API admission is queue acceptance; upload rejection remains pending for ordinary outbox retry. Local notification text stays literal.
- Heartbeat and notification jobs remain live after asynchronous provider admission until the first authoritative terminal final/error event, cancellation, or bounded timeout. Record their complete accepted event streams; an admission status such as `Codex turn started` is never completion, and late/duplicate terminal events cannot finish a job twice.
- Inject the exact notify.on selection key and explicit same-operator fallback rule for every communication dispatch, including preserved custom creation/chat templates, without rewriting those files.
- Assemble every ordinary, `/task`, and `/goal` communication prompt through the same framework chat-guidance path so preserved custom templates retain the evidence-grounded honesty contract exactly once before role-specific persistent instructions are appended.
- Own the primary-only stalled-conversation scheduler and ordinary same-session recovery dispatch. Coalesce startup/reconnect with a five-minute scan, fence the final durable reservation through provider admission under the exact cross-process election term, fence per-conversation active work, use exact private correlation plus durable task/goal source links, and require relevance validation plus one visible handled-or-skipped response. Admit the durable runtime job before reserving execution correlation, and roll back only the attempted source reservation on every pre-provider or harness-send failure so failed follow-ups preserve older active execution state without suppressing later recovery. Remote recovery admission requires both a connected enabled transport and its installed ordinary response router before reserving the source. Route every admitted recovery turn's canonical activity and terminal events through that conversation router; expose only the selected live TUI's overlap count through caller-scoped shared state, and stop activity before terminal delivery. Local recovery terminals remain durable in their named CLI/TUI conversation and follow their explicit private recovery marker into the live transcript. The first upgraded process activates forward correlation without legacy inference or replay; settings apply live, generated-reply redelivery remains out of scope, and status exposes owned copies of static reason counts. Diagnostics retain at most 100 scan-local conversation/candidate decision slots per scan plus aggregate counts; no recipient, private source identity or body is logged. Selection and atomic reservation use the same recent-window history contract, preserving exact old-timestamp coverage without retaining old bodies.

- Successful model/property selection returns the canonical model action row as `SavedControl`; the same formatter owns its label and effort/service description in configuration screens.

- Validate local CLI/TUI message names, text and correlation metadata at the shared admission boundary. Fence at most 64 concurrent source-ID admissions before hooks/dispatch; return explicit duplicate errors to local clients while preserving remote duplicate suppression. Retained history remains the bounded-memory restart duplicate check, not an exactly-once/idempotency service; recovery scan limits never cap conversation length or block ordinary commands and messages. Persist responding request IDs and continuation/final-item metadata with terminal replies and deterministic local replies.
- After admission, persist returned command, hook, prompt-preparation, and provider-admission errors as ordinary correlated `error` history entries before returning them to the transport, recording the redacted request first when a hook fails before ordinary history append; provider error events remain owned by the existing terminal emitter. Preserve trusted message-hook transformations; hook cancellation replies and transcript-visible TUI selection confirmations also use ordinary saved replies. Reloaded transcripts, resume branches, committed events, and bounded agent context share these records; never turn an admission failure into provider completion or recovery coverage, and retain pre-admission validation, duplicate, and strict-follow-up rejection fences.
- A terminal result for a cancelled queued request settles that request's history and activity only while its shared supervisor execution is still active. Preserve the active job, streamed partial text and execution correlation until the provider terminal; do not treat per-request cancellation as proof of provider termination.
- Conversation settlement uses an error-returning consumer. Freeze the non-continuing, non-request-only execution's source set before hooks or either partial/result write, retaining that admission fence on either persistence failure. Sync the transformed terminal reply and its exact frozen execution/source coverage in one history record before releasing correlation, stream text or the job; continuing and request-only results never freeze or cover the shared execution. Partial error output and the result use distinct private retry receipts, with a stable hook event ID for that emitter attempt. Failed persistence retains pending state; the existing void event boundary reports an explicit unsaved-result error and a degraded live job. The legacy emitter retains controller-local receipt/activity identity; private worker replay instead supplies its stable receipt, frozen source coverage, captured request-only state and retained partial output. Normal admission/follow-up composition remains unconnected. Hook and external delivery effects remain at least once; there is no automatic settlement retry or arbitrary external-effect transaction.
- Headless hosts may opt into a content-free ongoing operational projection through Runtime: UTC, level, stable component and event only. Never mirror diagnostic bodies, prompts, source identities, provider payloads or credentials; normalize caller-supplied TUI event names in this projection. Interactive hosts leave the writer unset.

- Autostart action results refresh the same form row to its opposite action after verified completion. Native inspection failures display unknown state with a retry action; failed mutations retain their errors and return fresh state. Preserve unsaved field values and selection.

- `/update` applies the owning npm or GitHub installation update and requests coordinated restart of all its instances; `/update check` is read-only. Validate and publish complete script bundles through `updater` before the process update request, and leave npm replacement to its stopped-process launcher. Pass the validated updater result through the owner shutdown request so npm can skip unnecessary replacement when current. Errors remain visible without discarding the prior installation. Keep slash catalog/help aligned.

- Recovery advances lexical conversation batches across scans, processes complete history pages until it finds eligible work, and admits at most 20 sources per conversation turn and 20 turns per pass. Deferred conversation/dispatch batches schedule a coalesced continuation, and remaining durable sources stay eligible for later passes. Bound body excerpts to 48 KiB and require full-source inspection through the authoritative history path when text is omitted. Source-link scans retain only candidate matches, read directory batches and bounded YAML metadata, and never use a lifetime document-count cutoff.
- Register every reserved batch source in the shared execution and persist its admission correlation. Terminal results and accepted cancellation cover that exact execution source set; rejected dispatch rolls back only the sources added by that attempt. Keep batch identities internal to application dispatch, outside the public message schema.

- Notification prompts freshly read only the exact authorized original conversation through the same application RecentBounded selection as chat, including live message/rune limits, timestamps, roles and prior notifications. JSON-delimit the transcript as untrusted data separately from task evidence, and substitute it after framework rendering. The complete prompt keeps the 128 KiB boundary and 4 KiB reserve; trim only the oldest context when necessary and reserve useful task head/tail evidence. Missing/unauthorized origins and real read errors fail closed without redirecting context.
- Task alerts use exact enabled notify.origin and selected notify.on outcomes, never global recent-user selection. Explicit fallback_origin / --fallback-origin may name a local conversation or private Telegram/WhatsApp route only when the workspace owner established same-operator ownership; allow-list membership, recency and cached identity are insufficient. Revalidate both destinations through ordinary application delivery, reject group escalation, and suppress fallback after primary authorization is revoked. For a configured fallback only, a TUI is available only when at least one unexpired client currently selects that thread; cleanup transition protection alone is insufficient; ordinary local delivery without fallback still commits saved history. Stable history delivery identity is checked at both explicit destinations before retry, so a committed fallback cannot later switch destinations. Pending and failed remote attempts create no delivered transcript entry; queue admission never implies send or receipt.

- Resume screens carry the history snapshot byte offset obtained with their transcript; notifications appended after that boundary remain visible when the TUI binds its selected thread. A new conversation starts at offset zero.
- `/new` requires the caller's explicit TUI instance identity. Create its durable history and publish that instance's selected conversation under the live-registration/cleanup boundary before emitting the screen; validation or history failure returns an error without exposing a new selection. Keep the prior cleanup protection and perform this work outside the TUI event loop.

- RecordJobDelivery is the fallible worker event boundary. Sync one bounded redacted archive snapshot and its private worker/sequence/cursor receipt together, including empty or truncated events; rollback in-memory output/prefix on write failure. Use the exact lease work ID for job identity even when the agent has already moved its document; reject a conflicting readable document ID. Reopening the same workflow archive retains its receipt and public identity; Runtime.Close releases its ownership lock without inventing provider completion. An authenticated immutable worker journal may replay an earlier prefix; reject gaps and changed last events, and require a later durable provider reservation before a different execution starts a new prefix in the same archive. Receipts remain absent from public summaries/output and never influence workflow decisions. Normal CLI composition does not yet select worker-backed application dispatch.

- Ordinary worker heartbeat/notification jobs use their independent admission WorkID and original start time for archive restoration; a referenced task file supplies no replacement task identity or parent linkage. The private Manager uses the same fallible archive delivery boundary as workflows. Normal production dispatch remains controller-owned.

- Job message/ping/kill route through the orchestrator execution owner, including a privately bound surviving worker. Local harness controls retain their existing callbacks; worker controls validate the exact durable claim and reserve inside the worker. Preserve operator authorization, local acknowledgements, cancellation reservation and runtime cleanup behavior. This does not enable normal worker-backed conversation dispatch.

- When the Manager has a bound worker, every settings surface uses worker-owned canonical save/reload and dispatch publication rather than a controller callback. Validate model/service capabilities through that worker, fence expected canonical/runtime snapshots, reconcile a lost reply by authenticated inspection without resending, then publish only the confirmed canonical snapshot under exact ownership. Failures preserve settings or report an unconfirmed commit; do not rollback native autostart after an unconfirmed remote commit. Native registration remains an external controller-owned side effect requiring explicit inspection after uncertainty, not a crash-atomic worker transaction. This private binding does not enable normal application composition or conversation adoption.

- ConsumeConversationDelivery runs only inside the worker client's exact-owner callback, without RPC or IsActive. Validate the shared descriptor, canonical conversation name, native delivery identity, same execution/job and complete retained source set before effects. Reuse the ordinary hook/media/history pipeline with stable worker/sequence/cursor receipts; sync one terminal reply with exact coverage and the transformed private archive receipt, then propagate downstream errors before job release/cursor commit, retaining a visibly degraded job on failure. Downstream receives the same stable delivery identity and must deduplicate its own effects; hooks/external delivery remain at least once. Worker-owned terminal-streamed text survives committed deltas and controller replacement without replaying stream state into the controller; preserve it with the stable partial receipt if hooks or outbound validation convert a provider final into an error. Reopen only the exact conversation WorkID/kind with no workflow phase/attempt, preserving number/generation and one provider step. Metadata/partial text stay absent from public archive output, and archived conversation inspection never displays its private execution WorkID. This private single-batch consumer does not enable normal dispatch, source admission, follow-ups, automatic attachment or channel lifecycle.
