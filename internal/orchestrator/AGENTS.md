# Markdown Orchestrator DOX

## Purpose

- Own durable task/goal workflows, claims and leases, recovery, review policy, semantic heartbeat, direct notification-agent dispatch, and ordinary delivery reconciliation.

## Local Contracts

- Treat Markdown as source of truth, claim queued phases atomically, fence provider work with phase-specific leases, preserve task-goal round links, and enforce configured transitions and review overlays.
- Recovery dispatch retires any ended local execution handle and resets the previous execution state and error before admission, preserving the public job number and archived history. Ignore events for retired handles. `recovering` covers restart preparation only: structured provider running evidence or successful admission returns the lease to `processing`, retaining the recovery count and journal. Serialize admission updates with provider events so terminal `awaiting_transition` cannot be overwritten; provider completion still requires durable transition reconciliation and never changes task/goal status by itself.
- Lease creation and retirement belong to the serialized scan. Asynchronous recovery, provider events, admission/error updates and control continuations must read and update the current execution under that same scan boundary; never recreate a retired lease, overwrite a replacement owner/session, or replace unreadable state with a cached snapshot. Keep provider sends outside the scan lock. Late completion still settles process-local jobs without requiring a durable lease.
- Obtain agent-authored timestamps from the current environment clock; waiting requires a concrete external condition, and recovery may not bypass live ownership or required review.
- For every task `done`, `failed`, and `cancelled` transition and every actionable unscheduled `waiting`, directly start one ordinary asynchronous notification-agent job. Re-read and validate enabled notification metadata plus the selected outcome before prompt construction. Supply task evidence exactly once: preserve a safely fitting document in full, otherwise use a deterministic valid-UTF-8 beginning/recent-end JSON projection with an explicit untrusted middle-omission marker, omitted-byte count, and exact JSON-encoded absolute path for inspecting the complete authoritative Markdown. Budget that projection only after rendering the customized template, framework guidance, scope discipline, and persistent notification instructions; retain a documented 4 KiB safety margin below the 128 KiB provider boundary, and reject oversized non-task sections precisely. Supply a shell-safe command with the absolute executable/workspace and exact task origin already filled in, using `--message \"Hello there\"`; an optional `notify.fallback_origin` names an explicitly owner-established same-operator local or private remote conversation and is attempted after direct delivery or live presentation fails while direct authorization still holds. Persist pending delivery failures with bounded retry for at most 48 hours from durable creation; at expiry retain an inspectable `expired` terminal failure with no retry schedule and never retry either origin. Never infer a remote fallback identity or use recent-authorized routing for a task. Direct the agent to change only the message. At render time, omit obsolete delivery paragraphs from preserved workspace overrides while retaining their unrelated custom decision and writing guidance. The agent alone decides and edits task progress with its send, skip, or CLI failure; do not parse provider output or create notification-specific persistence, claims, bindings, results, recovery, or replay. Do not bind semantic-heartbeat guidance to a task origin.
- Admit manual semantic heartbeats through the same scheduler loop and provider fence as timer ticks; provider release after either mode owns the next fixed-delay deadline. The elected primary alone invokes the shared cleanup callback on an eight-hour cadence using the live retention value.
- Heartbeat reminder policy belongs entirely to the agent: it inspects bounded waiting-task progress, judges inactivity and usefulness, invokes the ordinary notification CLI with the exact authorized task origin and any explicit owner-established fallback, and journals a send/skip/failure in that task. Recent-authorized routing is reserved for otherwise originless unambiguous alerts. The manager only triggers the heartbeat and injects this rule; it must not implement reminder queues, timers, thresholds, eligibility, identity links, correlation, acknowledgement, deduplication, contingency branches, or delivery orchestration beyond the ordinary notify primitive. At render time, omit retired read-only, original-origin-only, and action/JSON-result paragraphs from preserved workspace heartbeat overrides while retaining unrelated customized inspection and repair guidance.
- Treat heartbeat harness dispatch as worker admission, not a result protocol. Keep the provider fence through terminal release, ignore every provider payload, and persist no framework heartbeat action, finding, health, incident, escalation, retry, or notification state. The agent uses ordinary Spynel CLI inspection and applicable Markdown workflow contracts to make the smallest evidence-backed repair, journals each durable change itself, and may request the existing serialized orchestrator trigger. Task terminal and actionable unscheduled waiting transitions dispatch their notification agent directly.
- Require application job admission before dispatching task, review, goal, heartbeat, or notification-agent provider work; an admission failure stops that dispatch and follows the owning workflow's ordinary error path. Forward admitted provider-neutral streams to the application job recorder without parsing their text. Archive capture never changes lease, transition, notification, or recovery decisions.
- Run heartbeat and notification agents through the same ordinary provider-neutral job lifecycle: `Send` admits asynchronous work and never implies completion, `Codex turn started` is nonterminal, and the first non-continuing final/error event, cancellation, or bounded timeout ends job ownership exactly once. Keep the complete accepted event stream through that boundary, ignore late/duplicate terminal events, and retain heartbeat cadence/non-overlap as a separate scheduling fence until provider release.
- Serialize terminal-task retention with goal scanning. Keep every settled task linked to any nonterminal goal in the live status folders until that goal reaches a terminal outcome; an incomplete nonterminal-goal index must fail safe by protecting goal-linked tasks.
- Own exactly two fixed workflows under `.spynel/tasks` and `.spynel/goals`, with fixed prompt paths, transitions, and 30-minute/task and two-hour/goal stale thresholds. Do not persist route definitions in configuration, leases, or goal front matter. Task/goal creation prompts, scans, recovery, retention, status, and linked rounds share these canonical folders. Apply scanner interval changes by synchronously resetting the production timer and fence already-selected stale timer generations through the scan lock.

- Metadata-only consumers use bounded YAML-header reads without loading accumulated progress. Goal handoff context retains a 32 KiB tail of linked-task paths with explicit full-cohort inspection guidance; eligibility and review still inspect the complete current round.

- Notification prompts freshly read only the exact authorized original conversation through the same application RecentBounded selection as chat, including live message/rune limits, timestamps, roles and prior notifications. JSON-delimit the transcript as untrusted data separately from task evidence, and substitute it after framework rendering. The complete prompt keeps the 128 KiB boundary and 4 KiB reserve; trim only the oldest context when necessary and reserve useful task head/tail evidence. Missing/unauthorized origins and real read errors fail closed without redirecting context.
- Task alerts use exact enabled notify.origin and selected notify.on outcomes, never global recent-user selection. Explicit fallback_origin / --fallback-origin may name a local conversation or private Telegram/WhatsApp route only when the workspace owner established same-operator ownership; allow-list membership, recency and cached identity are insufficient. Revalidate both destinations through ordinary application delivery, reject group escalation, and suppress fallback after primary authorization is revoked. For a configured fallback only, a TUI is available only when an unexpired client currently selects that thread; cleanup transition protection alone is insufficient; ordinary local delivery without fallback still commits saved history. Stable history delivery identity is checked at both explicit destinations before retry, so a committed fallback cannot later switch destinations. Pending and failed remote attempts create no delivered transcript entry; queue admission never implies send or receipt.
- Heartbeat judgment inspects blocked work, missed alerts, delivery failures and unanswered questions using existing durable progress, bounded original-thread context and source correlation. An unrelated later reply never settles a question. Prefer the exact authorized task origin and its explicit owner-established fallback; recent-authorized routing is reserved for otherwise originless unambiguous alerts. Journal actual send/skip/failure and missing prerequisites; no framework reminder engine, new correlation state or provider-output parser exists.
- Heartbeat first traces the root dependency, policy applicability, existing authorization and executable independent work before imposing an external gate. Resume proven safe work through ordinary lifecycle; a fresh wait or absent prior alert never suppresses the first concrete prerequisite question. Use exact task routing metadata privately and necessary bounded question/reply evidence without exposing either. Failed/absent attempts and queue admission are not delivered questions or answers. Validate relevant answers before resuming the affected dependency and avoid repeat escalation after resolution. Render-time removal of the retired stock body-free/question-inspection ban preserves unrelated workspace customization; it never grants new access or reads histories itself.
