# CLI DOX

## Purpose

- Own public command parsing, process lifecycle, plain automation commands, static docs dispatch, and server-runtime composition.

## Local Contracts

- Primary startup supplies the current bounded canonical-settings snapshot when binding its independent worker. Installing the selected harness or correcting an unavailable selection reconciles that worker through its existing settings transaction, without killing it or dispatching a provider turn. Missing harnesses keep the configuration/status service reachable; retained executions still fence structural changes.

- Own process diagnostics at the native executable boundary. Direct Linux/macOS externally managed server launches tee descriptor 2 through a private reader of the same executable; supervised executors use their surviving native parent as the same bounded capture owner, preserving the original terminal destination and a bounded 64 KiB excerpt before existing runtime-log redaction/entry limits. Wait for bounded reader readiness before redirecting; retain a spare pipe reader until restoring stderr so reader loss cannot turn ordinary application writes into SIGPIPE. The reader follows EOF, ignores terminal termination signals, never runs application work, and has a bounded shutdown join; it does not supervise or restart the application. Restore stderr before exec/restart. Reader/storage failure leaves a content-free warning and must not change the original application result.
- Private `__diagnostics crash|exit` modes are harness-free log sinks, not public control commands. Their bounded metadata carries only log directory, native PID/run, build identity and observed exit result; never arguments, configuration, environments or conversation data. Native-supervisor exits also retain supervisor PID, executor-start and observed-exit UTC times; signaled exits report optional bounded visible-cgroup OOM-kill cumulative counts/deltas only as unattributed context. Missing counters remain unavailable, never zero evidence; a signal or counter delta cannot identify a victim/sender or prove OOM. Attribution requires timestamped host kernel victim or audit/container-controller records with PID mapping. The npm parent receives metadata on descriptor 3 and records its actual native exit code/signal after close. Process `process_started`/`process_end` and parent `native_exit` are distinct from runtime `session_start`/`session_end`; missing end evidence means unknown/unclean termination, never a proven crash or OOM. Keep command-failure causes and recovered TUI panic stacks behind the central private redaction boundary.
- Both stderr readers and native exit recorders register through the updater's existing private process registry as diagnostic helpers before reading protocol input. They are visible to verified kill/uninstall discovery, never application restart targets, and deregister on completion. Preserve that shared process classification rather than filtering helpers independently in update callers.
- Private `__provider` helpers register as provider guardians before starting work. They validate inherited private-lock and lifetime-pipe descriptors, pass provider stdio unchanged, and never initialize a workspace, join election, start channels or enter native executor recovery. Keep them visible to verified stop/uninstall discovery while excluding them from application update/restart targets.
- Private `__worker` registers as a harness worker, then delegates bounded stdin bootstrap, readiness and its signal-aware independent supervisor lifetime to `harness.RunWorker`, injecting the orchestrator-owned workflow validation, continuation and reservation callback and config-owned canonical settings callback, plus the application-owned conversation source callback, including atomic stalled-message recovery reservation/admission, canonical policy revalidation and exact ordinary-batch restoration only after proven non-admission. It starts no channels, application service, orchestration scanner or election ownership. The private runtime also supports exact same-execution conversation follow-ups through that existing callback; private Manager follow-up composition is connected.
- Managed Telegram and WhatsApp builders bind recipient authorization to the live configuration store, returning unavailable authorization when disabled; snapshots alone never authorize a retained adapter generation.
- Route shared behavior through the same application service and local API as interactive channels; deterministic commands must not start a harness merely because no owner exists.
- Before an ownerless plain-CLI `/cleanup`, hold the shared election mutation boundary through the destructive operation and recheck that the primary lease is absent and the durable clean-release grace period has expired. If ownership appeared or failover is still fenced, join the healthy owner or fail closed during the transition; never run cleanup from a separate process-local service beside an owner or an already-open successor awaiting promotion.
- While running a workspace server/election, absorb SIGTSTP from startup through shutdown so terminal job control cannot suspend a shared primary. Unregister the signal channel afterward. Ctrl+Z has no shell-suspend action; explicit SIGSTOP cannot be prevented and still requires operator recovery. Never steal a fresh lease because readiness fails.
- Primary diagnostics distinguish delayed scheduling, election mutation-lock waits/holds, unchanged stale-term renewal, replacement/handoff and controller/API shutdown. Log only instance identity, fixed reasons and timings; renewal or diagnostic observation never bypasses the election fence.
- Preserve bounded stdin, attachments, final/stream/NDJSON output contracts, strict active-turn follow-up checks, and platform-specific restart behavior.
- Keep `model`, `effort`, and `speed` aliases on the shared command path so noninteractive clients inspect, set, reset, and validate the same model properties as the TUI.
- Generate one private stable source-message identity before each CLI submission and retain it across loopback dispatch so retries cannot duplicate work.
- Keep `docs` offline and workspace-independent. `spynel notify` requires exactly one of explicit `--origin ORIGIN` or `--recent-authorized`, independently revalidates workspace/origin authorization through the application service, and remains one ordinary delivery command with no task-transition flags or task-log side effects. Recent routing exposes no resolved destination and fails closed on ambiguous authority/activity. Operator positional input may remain compatible, while generated transition-notification guidance still uses concrete `--workdir`, `--origin`, and `--message`. A notification agent records success, skip, or command failure by editing the task itself.
- Canonicalize bare interactive launch context before configuration discovery. An uninitialized child may enter its discovered parent or initialize locally only through the required pre-election choice; explicit and noninteractive commands retain deterministic non-prompting discovery.
- Poll owner shared state for TUI runtime, durable-work, and caller-scoped selected-conversation activity changes; translate latest activity counts through a bounded nonblocking bridge into balanced canonical TUI events, including startup and overlap counts larger than the output buffer, and leave bounded work diagnostics off the visual header.
- Keep asynchronous local recovery results durable in the named CLI/TUI conversation and supply the TUI its startup snapshot offset and history directory so it can follow explicitly marked recovery terminals and notifications from the selected thread, preserving durable order and error role without treating recovery terminals as acknowledged task notifications. Pass the selected conversation into every notification acknowledgement instead of capturing the startup identity.
- Admit each TUI's selected conversation into the owner's renewable live-conversation lease boundary before reading its startup history, seed startup from the caller-scoped state returned by that registration rather than an earlier readiness snapshot, retain that lease for its complete interactive lifetime, and renew the displayed identity after switches.
- Every newly allocated startup conversation, including the first in a freshly initialized workspace, enters the same welcome state as `/new`. Select this from whether history was resumed, not whether this process became primary. `/clear` keeps its existing empty-chat behavior.
- When an interactive TUI start observed an existing fresh primary, print one pre-alternate-screen connecting line followed by success or a sanitized actionable failure. Keep first-owner, headless, remote-channel, redirected, and automation startup output unchanged.

- Expose `events --conversation NAME [--after CURSOR]` as a long-lived single-attempt NDJSON subscription to an existing primary. `send`/`followup --request-id` retain client correlation; `send`, `followup` and `events --socket` explicitly select one private socket without local configuration/election discovery. JSON dispatched errors stay on protocol stdout with generic stderr failure, and continuing finals/errors do not end a request.
- `serve --socket PATH` adds the optional Unix listener only when this process acquires a new primary. Keep the loopback listener, all TUI attachment semantics and election fences. Headless primary terms opt into the Runtime operational stderr projection; TUI-hosting terms do not.

- Keep standalone bootstrap `install-bundle` independent of workspace initialization. Reuse updater ownership to route explicit update completion and ordinary restart through the stable installed entry point, preserving primary/job shutdown and init continuation arguments. Authorize proactive standalone checks only in an actual interactive TUI launch without automatic-startup or skip-check flags.
- An ownerless standalone update restarts into `version`; for NDJSON output, use `version --quiet` so the new executable runs successfully without appending plain text or another terminal event after the correlated update acknowledgment.

- Internal `uninstall-bundles` is workspace-independent. Discover the current global npm root before elevation, retain the original HOME/PATH/user identity across one required native sudo authorization, and coordinate updater removal with startup cleanup for both standalone and npm installations. The public `uninstall.sh` uses the checksummed native bootstrap so cleanup runs outside either installation.

- `spynel update` acts on the caller's managed installation without joining a workspace primary; bare update applies and restarts all its instances, `check` only checks. Channel updates select their primary's installation through the shared updater. Register each server/TUI for its entire election lifetime and translate the updater restart signal into ordinary graceful shutdown and exec. Internal launcher coordination commands are workspace-independent. `spynel killall` stops verified processes across installations and asks startup ownership to stop matching services without removing future registrations.
- Publish npm update handoffs atomically through the common run-completion boundary, including native-supervisor exits. Replace only a prior private regular handoff file, reject unsafe paths/files, and return publication errors before exposing exit code 75. Exit-code inspection has no file-writing side effects.
- Plain CLI message completion waits for both a terminal reply and handler return before success, so post-acknowledgement update/control requests are visible before cancellation or service teardown. Asynchronous admission still waits for its later terminal event; handlers that return without any event complete without a reply.


- Linux/macOS manual bare, interactive init-continuation and serve launches use one native supervisor and an authenticated private executor of the same executable. Select this before workspace/runtime construction. The executor owns election/UI/providers; the parent owns direct-child wait, terminal restoration, bounded stderr and three cancellable retries at one/two/three seconds after admitted unexpected exits. Reset the budget only after one minute of admitted operation. Normal quit, acknowledged stop/update/restart and startup failures never enter crash recovery. One-shot commands remain single-run; --automatic-startup selects external service restart ownership.
- Harness ownership is a private nonblocking OS lock on the stable OS per-user-config spynel/harness/<canonical-workspace-hash>.lock file; file presence, contents and age are never ownership evidence, and the file is never unlinked. Keep process locks off shared workspace mounts, whose file-lock semantics may be unavailable. Each provider runs behind a private same-binary guardian retaining the lock and a separate owner-lifetime pipe. Owner loss or cancellation terminates and joins the direct provider before the guardian exits; the OS releases ownership when all holders exit. Busy ownership and pending confirmed shutdown retry automatically and publish harness readiness when resolved. Provider admission does not suppress native executor crash recovery. Keep arbitrary escaped descendants and remote effects outside this direct-provider guarantee; durable task recovery still owns reconciliation, with no supervisor task replay or lease repair.
- Supervised updates preserve the same supervisor PID with a new generation and a verified new executor at target version/readiness; direct externally managed instances retain same-PID exec. Supervisors remain registered without a child during backoff and latch stop before kill/uninstall teardown. Resolve the stable installed image and replace the supervisor itself before a new executor. Application readiness waits through the existing 30-second election fence within a 40-second shared budget; coordination allows 60 seconds. Never delete a fresh primary lease or fabricate readiness.

- The dedicated shell update --json owner generates a private request identity before mutation, emits exactly one final/done correlated acknowledgment and re-execs version --quiet without extra protocol output. Check-only JSON remains an updater-state snapshot.

- Ordinary notify accepts an explicit owner-established same-operator private remote fallback as well as local fallbacks; this is an association supplied by the operator, never inferred from allow-lists or recency. Admission remains queue acceptance.

- With an explicit private worker binding, primary orchestrator readiness polls authenticated worker availability with the existing election retry interval and caller cancellation; the inactive controller Supervisor cannot release or indefinitely block that gate. Version-changing update coordination remains unfinished.

- The elected continuous primary opens the exact current-config/compatible-protocol independent worker before application startup and binds the Manager outside election callbacks. Discovery failure refuses startup without a local-provider fallback; unavailable adapters retain authenticated inspection/settings recovery. Controller teardown cancels and joins consumers, releases or hands off election ownership, then closes application resources and detaches the worker client. One-shot ownerless CLI services retain local supervision. Verified stop/uninstall still discovers the worker registry role. After an exact primary renewal, only shared native ESRCH evidence rebuilds the term and its fixed binding; live endpoint failures and uncertain identity never authorize replacement. Teardown joins the old consumers before ordinary discovery launches a worker, and existing workflow/source recovery preserves cancellation and provider reservations. Version-changing updates, broader cross-worker journal recovery and complete release qualification remain unfinished.

- Protocol 18 is the explicit worker compatibility boundary, including behavior and schema. It adds canonical global verbosity to the prior speech idle setting; older workers cannot preserve the new setting. Bump it whenever a successor cannot safely consume/control the previous worker. Its configuration digest binds that protocol and every serialized runtime setting except the native client version. A same-protocol controller with an otherwise exact selection may adopt across release versions without reconfiguration or another provider turn; native PID/start/executable/generation verification and authenticated exact-term inspection still apply. The retained worker keeps its native registration and original provider client version. Canonical settings derive from authenticated worker configuration, and direct attempts to change its workspace/version still refuse. Live incompatible protocols fail closed. A primary may reconcile changed runtime selection or retry an unavailable adapter through the existing authenticated canonical-settings transaction after native identity, environment, workspace and election-term verification. The worker retains its original version and identity; structural replacement still refuses retained executions or unconfirmed cleanup, and inference changes retain their active-safe fence. When no provider was available, a validated selection whose startup fails may commit as unavailable only after confirmed cleanup; this keeps configuration reachable without claiming readiness or replacing working providers. No automatic stop, admission retry or compatibility reader is added. A strictly validated current-schema rendezvous with a different positive protocol may authorize replacement only after native verification confirms death; pending guardian cleanup retains the existing bounded harness-lock wait. Malformed or changed schemas and live/unknown native identity still refuse replacement. This resolves version-only discovery compatibility, not complete coordinated update/stop/uninstall or final release qualification.

- Register public application CLI requests and subscriptions through the updater as application clients for their entire command lifetime, including stdin preparation and explicit sockets. They remain visible to verified stop/uninstall without being restarted alongside servers/TUIs or blocking coordinated updates. Keep this at process dispatch so in-process application calls cannot overwrite a server registration. Offline docs/help/version and standalone installer/update ownership retain their existing boundaries.

- Internal check-restartable accepts --worker-protocol N, with 0 explicitly unknown and omission selecting the local protocol. Native npm handoffs carry the shared updater-owned target protocol alongside exact version/arguments/install intent. CLI and channel updates retain the same shared prepublication compatibility check and explicit drain/stop guidance.

- Protocol 16 preserves complete crash-left terminal journals at the shared harness owner before new admissions. Native/election ownership and matching current configuration gate bounded private copying; consumers retain the original delivery receipts across worker generations. Unfinished prefixes remain available for ordinary source/claim reconciliation without invented completion. Corrupt or uncertain current-schema state refuses replacement; unexpected failures preserve discovery, while explicit stop/orphan cleanup remains destructive. The owning harness contract defines the exact limits and unsupported previous-schema boundary.

- Ordinary notify carries optional `escalation_key` (`--escalation-key` on CLI) only with explicit original/fallback routes. It selects the owner-associated fallback without requiring primary delivery failure, preserving live route checks and ordinary outbox retry/deduplication. Reuse the same decision key/message; recent-authorized routing cannot be combined. Admission remains queue acceptance.

- Ordinary notify cancellation accepts only exact original origin plus `--cancel EVENT_ID` / `cancel_id`; it rejects send/routing alternatives. Return confirmed terminal state without exposing delivery content or claiming a retraction. Keep client/server and CLI validation synchronized; older owners lacking confirmation must fail visibly.

- Own one shared speech worker per channel-supervisor lifetime. Apply idle-timeout saves through the application refresh hook, exclude that timer-only setting from transport restart fingerprints, and close the worker after the supervisor stops before reporting channel shutdown complete. Speech close refuses new work immediately; an uninterruptible native call retains its resources until completion or process exit and cannot hold restart on the transcription lock.

- Expose `verbose [on|off|auto]` on the existing shared command path. Bind both remote adapters to live global verbosity without restarting them; carry it through owner shared-state polling to every attached TUI. Explicit send --stream/--json and integration subscriptions remain unfiltered.

- Private hold-worker-update registers a native application client and holds updater launch ownership over the npm parent lifetime pipe: readiness precedes npm replacement, EOF aborts and commit retires idle workers after publication. restart-instances first resolves paused/incompatible idle workers against the installed local protocol, then uses ordinary verified supervisor/application readiness. Shell updates register their finite native owner too. No new user configuration or public bypass exists.

- Native registrations advertise participation in the installation worker-launch gate as registry-only metadata. Unknown/incompatible replacement refuses an older application without that capability, even if it currently has no worker, so it cannot launch an unfenced predecessor during publication. Known-compatible restart behavior remains unchanged.
